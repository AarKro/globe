# Globe Café — 3D walkable room

Browser-based first-person walk-through of a stylized café interior, built with Three.js and Vite. `project_brief.md` is the authoritative spec — read it before making non-trivial changes.

## Commands

```bash
npm install        # once
npm run dev        # dev server (Vite)
npm run build      # production build to dist/
npm run preview    # serve the production build locally
```

No tests and no linter are configured. Verify changes by running the dev server and walking the room.

## Deployment

Pushes to `main` deploy to GitHub Pages via `.github/workflows/deploy.yml` (build → upload `dist/` → deploy). Vite uses `base: './'` (relative paths) so the build works under any Pages repo path — keep asset references relative or via `new URL(..., import.meta.url)`; never absolute root paths.

## Architecture

Vanilla ES modules, no framework. `src/main.js` wires everything and owns the render loop and overlay/pointer-lock state.

- `src/scene/constants.js` — tunables: placeholder room dimensions, eye height, walk speed, look sensitivities, FOV, bounds margin. Tune feel here, not inline.
- `src/scene/createScene.js` — scene, camera, renderer, resize handling. Pixel ratio clamped to 2.
- `src/scene/createGltfRoom.js` — **the active room**: loads `room_without_tunnel_and_door.glb` (the standard model — it omits the old built-in corridor tube and door leaf, leaving a clean doorway opening in the −x wall that the programmed tunnel connects through), recenters it (floor center → origin, floor top → y=0) via the `FLOOR` mesh and scales it ×5 to meters inside a `shell` wrapper group, adds the runtime `ceiling` (see below), a `windowScreen` plane on the −z wall (a tall storefront window for the street video — `WINDOW` is sized larger than the model's actual ribbon cut-out, painting the video down the wall so it reads as a big picture window), and `wooden_table_set.glb` clones at `TABLE_SET_PLACEMENTS`. Furniture lives in a sibling `furniture` group in plain world meters — only the shell carries the ×5 model scale. Also adds dark **night-backdrop panels** (`xWallSeal*`, `zWallSeal*`) just outside the café's open walls: the −x wall has the corridor mouth/doorway (`CORRIDOR_BAND`, z ≈ 3.95..5.95 — `min` is the café door's −z edge, set so the seal also covers the sliver where the model doorway is wider than the door) and the other walls are glass, so without these the entrance's daytime sky dome would leak through; the panels read as dark night beyond the glass. Openings kept: the −z storefront window and the −x corridor mouth (the tunnel in). `STRIP_MESH_NAMES` is empty now (the model already lacks the tunnel/door). Returns `{ room, bounds, spawn, windowScreen }`. `INTERIOR`/`WINDOW`/`CORRIDOR_BAND`/`CEILING_Y` are measured constants — re-measure (e.g. with a GLB AABB script) if the model or ROOM_SCALE changes. `room.glb` (the old model, with the tunnel/door baked in), `empty_coffeeroom.glb`, `coffeshop_room.glb`, `cover_chair.glb` are unused leftovers (excluded from the build).
  Note: the table set's wood texture is genuinely pale ash — cream-colored furniture is the asset's real look, not a texture failure.
- `src/scene/createRoom.js` — the original placeholder room (named groups under a `room` root). Currently unused but kept as a dependency-free fallback; returns `{ room, mediaSurfaces }`.
- `src/scene/createLights.js` — hemisphere fill + directional key + two point lights, positioned relative to the walkable `bounds` so it works for any room.
- `src/scene/createVideoSurface.js` — media-surface manager driving the café **window**. Gradient CanvasTexture fallback by default; `setSource(url)` swaps in a muted/looping/playsinline VideoTexture and falls back gracefully if autoplay is blocked; `restart()` seeks the clip back to 0. `createVideoSurface(meshes, { coverAspect })` center-crops the clip to the surface aspect (the window is a tall storefront panel, ~2.9:1). main.js wires it to `windowScreen` and, in `selectTheme`/on the start gesture, points it at the per-theme **street video**; the clip plays through the whole entrance walk, so main.js calls `restart()` when the player enters the café (`sequence.place` → `cafe`) so the window starts from frame 0 when it first comes into view. Videos live in `public/videos/{tokyo,newyork}.mp4` — both ~55 s, compressed with ffmpeg (720/640p H.264, audio stripped, faststart). Keep them similar length/size so neither lags the other.
- `src/controls/playerController.js` — first-person camera: yaw/pitch (YXZ euler, pitch clamped), ground-plane movement, position clamped to the walkable rect `{minX,maxX,minZ,maxZ}` passed in. Owns the camera; nothing else moves it.
- `src/themes/` — city theme system (one active; rotated monthly, toggled top right). `themes.js` defines each theme: a `lighting` block applied to the existing lights/background and a `buildDecor()` returning a decor group built from `decor.js` helpers (canvas-texture signs, neon tubes, bulb strings, torii, steam pipes, Edison pendants, `makeVendingMachine`, `makeWallClock`, `makeImagePanel` for framed photo posters, and `addPaperLanterns` which hangs the `japanese_paper_lantern.glb` model — loaded async/fresh per build, normalized to a fixed height, so theme-switch disposal stays clean). Decor is **spread across the three usable walls** via the mount-line constants `BACK_WALL_Z` (+z), `LEFT_WALL_X` (−x), `RIGHT_WALL_X` (+x) — each faces into the room (rotation.y of π / π/2 / −π/2). Avoid the −z window wall (street video, only the neon window frame goes there), the −x doorway band (z 3.6..5.95), and the bar (counter + shelves at +x/+z, x>2.3 & z>2.3). Each city leans hard into its own kit — Tokyo is cool neon (pink/cyan signage, stacked kanji signboard, vermilion torii, GLB paper lanterns over the seating, a glowing vending machine, window neon frame, framed Japan posters); New York is warm Americana (OPEN/COFFEE neon, GLOBE CAFÉ marquee, green street sign, diner wall clock, Edison pendants, steam pipes, bulb strings). Poster art is per-theme (`JP_POSTERS`, `NY_POSTERS`) — add files to `src/assets/images/` and reference via `new URL(..., import.meta.url)`. (`makeLantern`, the old procedural lantern, is now unused but kept as a fallback helper.) `themeManager.js` swaps decor (with full geometry/material/texture disposal) and retunes lights. The core shop — room model, furniture, player — is never touched by themes. Adding a city = one entry in `THEMES` + a button in index.html. Choice persists in localStorage (`globe-theme`).
- `src/controls/keyboardMouseInput.js` — WASD + pointer-lock mouse deltas.
- `src/controls/gamepadInput.js` — standard-mapping gamepad polling, radial dead zones. Left stick move, right stick look.
- **Entrance experience** — the player *spawns on a daytime street*, not in the café, and walks **+x** straight into it. It is **one continuous space, no teleport**: the entrance is laid out along the −x axis centred on the line `z = corridorZ`, threading through the clean doorway in the new room model's −x wall. A **programmed tunnel shell** (`tunnelShell`, a dark box) forms the corridor from the café mouth (`mouthX`) out to the façade (`facadeX`) — currently 17.2 m long (`mouthX` is fixed; `facadeX` and the street/spawn move to lengthen it). Order: street (sky dome + black façade) → façade door → tunnel (dark shell, neon rings, reactive floor) → café-mouth door → café. The whole street sits inside a seamless daytime **sky dome** (inverted gradient sphere, radius ~180) over a big cobbled ground plane — no edges, so nothing leaks. The camera's **far plane (320)** reaches past the dome. The long dark corridor with a door at each end keeps the daytime street out of the night café; the café itself is boxed in dark night-backdrop panels (see createGltfRoom) so the dome never leaks through its glass walls. The clean-brutalist BLACK café building (the façade at `facadeX`) is wide enough (`facadeZMin`/`facadeZMax`) to fully occlude the real café building (only ~2.4 m tall) standing behind it; the door sits at `corridorZ`, so the building is asymmetric. The street alley is narrow (`streetHalf`) to keep the player on-axis so the façade always occludes. **Everything in the entrance is unlit** (`MeshBasic`/emissive) so the global café lights can't touch it. It is **fully reversible**: both thresholds (street↔tunnel at the façade, tunnel↔café at the mouth) are real openings — the door swings and `liveBounds` swaps, no cut. (Earlier versions used a teleport portal + warm light-bloom white-out because the entrance lived far down +z; both are gone. `sequence.flash` is retained but always 0.)
  - `src/scene/createEntrance.js` — geometry (all along −x at `z = corridorZ`): a daytime **sky dome** (`skyDome`), a large cobbled ground plane, the black café façade box with its door (capping the tunnel's street end) and a **glowing white GLOBE logo** above the door (`makeGlowLogo` inverts the dark-on-white source art to white-strokes-on-transparent so it reads as lit signage on the black wall — `LOGO_URL`), the **programmed tunnel shell** (`tunnelShell`, a dark box replacing the stripped model corridor), **white neon ring hoops** inside it whose lit frontier runs `ringLead` ahead of the player (`resetRings()` replays it on each street entry), and the **reactive floor** (`InstancedMesh`; `build` trail + footstep `pulse`). Returns `{ group, doors:{entry,cafe}, setAccent, resetRings, update, dispose }`. Door seams/frames carry the theme accent (a single crisp line — brutalist); the rings and logo are white. The door neon rims (frame + leaf seam, in `entryRims`/`cafeRims`) show only when **both** doors are shut and the player is outside the tunnel — they all hide the moment **either** door starts opening (`ratio > 0.02`, so no lit rim shows through the open doorway, near or far) and whenever `place === 'tunnel'` (pure black). Doors are built in the x-y plane and oriented onto the x-normal walls via `placeDoorX`.
  - `src/scene/entranceSequence.js` — the reversible place machine (`street`/`tunnel`/`cafe`), continuous (no teleport). Owns the single mutable `liveBounds` rect; opens each door by proximity and, while open and in the corridor's z-band, extends the bounds through the opening so you walk straight through (the café case opens a channel through the −x wall at the mouth). Entering the tunnel **from the street** arms the audio hush and resets the rings; **from the café** it doesn't. `flash` getter always returns 0. Pure logic (imports only constants) — verifiable in Node.
  - `src/audio/entranceAudio.js` — music gated by place: **silent on the street**; on entering the tunnel from the street it stays silent (`hold()`) until the entry door shuts behind you, at which point a procedural **door-close clunk** (`doorClose()`) plays and the timed hush begins (`armHush()`), then the music fades in and **swells louder toward the café** (and back down returning); **steady in the café**. The music source is an **audio file** when one is present (drop loops into `public/audio/`, see `MUSIC_FILES` + `public/audio/README.md`), else a quiet synth pad + pentatonic arpeggio fallback — both run through the same `musicGain` swell, so behaviour is identical either way. `update(dt)` (every frame) drives the swell, silence timer, and (fallback) note scheduler. AudioContext is lazy in `resume()` from a user gesture; missing/blocked Web Audio is a silent no-op. Footsteps are diegetic (silent outside / during the hush). Sound on/off via the bottom-right toggle.

## Conventions and invariants

- **Input abstraction**: input modules produce normalized intent (move vector with x = strafe right, y = forward; look as delta or rate). The player controller never reads devices directly; new input methods (touch etc.) plug in by producing the same intent.
- Mouse look is an accumulated per-frame pixel delta (`consumeLookDelta`); gamepad look is a rate scaled by dt. Don't mix the two models up.
- Units are meters; player eye height 1.6 m, walk speed ~3 m/s, frame-rate independent via clamped `clock.getDelta()`.
- All meshes and groups are named — keep that up for future selection/animation.
- The walkable rect is the raycast-measured interior `INTERIOR` in createGltfRoom.js (x -7.19..4.79, z -6.0..6.0) — the floor and building shell extend past the interior room (exterior pavement), so mesh bounding boxes give wrong walls. The empty room GLB has no ceiling mesh, so createGltfRoom.js adds one at runtime (a `ceiling` box at `CEILING_Y` ≈ 2.45 m, lit from below by the lamps) to cap the interior — otherwise you see the background / distant entrance rooftops above the walls. Its back wall is glass left of the counter. Theme decor mounts on measured wall faces in themes.js (~0.1 m proud of the walls to avoid z-fighting). Re-measure both if the room GLB or its scale changes.
- Headless verification gotcha: the player controller re-applies yaw/pitch and clamps position every frame, so scripted `camera.lookAt()` is overwritten. In dev, set `window.__globe.freecam.enabled = true` first (exposed from main.js along with `scene/camera/bounds/liveBounds/entrance/sequence/THREE`). `bounds` is the fixed café rect; `liveBounds` is the mutable rect the player actually clamps to while the entrance sequence runs.
- The room GLB is a messy Sketchfab/Maya export (~1,100 nodes, 30 merged meshes, identified by `_<material>_0` name suffixes). Don't edit the GLB files; do model surgery at runtime in createGltfRoom.js.
- Keep it dependency-light: three + vite only. No framework, no physics engine (collision is a bounds clamp by design for v1).

## Non-goals (v1)

Jumping/crouching/head bob, physics, mobile touch walk controls, postprocessing, multiplayer. (Audio is now present — procedural ambience for the entrance; see `src/audio/entranceAudio.js`.) See the brief's roadmap before adding scope.
